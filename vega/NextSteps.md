## 🏗️ Build & Deployment Issues

- **O fluxo oficial "Port TV App to Vega" parou na Etapa 2 (Shared Prerequisites):** `which vega` não encontrou a Vega CLI no WSL; nenhum aparelho Vega conectado; o host é WSL (`grep -qi microsoft /proc/version` casou), então `host_supports_vvd=false` e o Vega Virtual Device não pode ser oferecido. O workflow manda parar e pedir um aparelho Vega físico. As fases 1, 2, 2.5 e 3 foram executadas mesmo assim, seguindo os documentos do workflow; os comandos da Vega CLI (`vega project generate`, `vega project install`, `vega project doctor`, build) rodam no GitHub Actions (Ubuntu 24.04), não no WSL.
- **Fase 4 concluída depois, fora do fluxo oficial:** modo desenvolvedor ativado no Fire TV Stick HD (2ª geração, Vega OS 2.0) a partir do container Docker no WSL; `vega device install-app` e `launch-app` funcionaram e o app abriu com foco inicial e navegação pelo D-pad corretos (2026-10-29). Fase 5 (revisão completa) segue em `release/ROTEIRO-DE-TESTE.md`.
- SplashScreen: `assets/raw/SplashScreenImages.zip` usa o logotipo "Hello World" sobre fundo preto (1920×1080, estático), gerado por `scripts/make-assets.mjs`. Troque pelo splash definitivo da marca se quiser (formato em `vega_splash_screen_manager.md`).
- **Vega SDK 2.0** (2026-10-30): `manifest.toml` exige Vega OS **2.0** (`[os.version] min = target = "2.0"`, recomendação do guia de migração da Amazon). A entrada `[[needs.module]] /com.amazon.vega.os@IVega_*` saiu do arquivo: o build do 2.0 a gera a partir de `[os.version]`. Todos os aparelhos Vega já receberam o OS 2.0 (Fire TV Stick HD: build 2602000052920). O app não tem código nativo, então as seções de APIs experimentais/obsoletas do guia não se aplicam.
- Campo da tela Buscar: num OS futuro, o Voltar num `TextInput` de uma linha dispara `onSubmitEditing` com `submitAction: 'previous'` (notas do SDK 2.0); `SearchScreen` ignora esse caso para o Voltar não disparar a busca.
- Testes (Jest): os mocks do `@amazon-devices/react-native-kepler` 4.0.x têm falhas (o `BackHandler` sai `undefined` porque o mock não exporta `default`; `Dimensions.addEventListener` não devolve `remove()`; os hooks de splash referenciam `Platform` sem importá-lo). `test/setup.js` corrige os dois primeiros e o teste mocka `src/launch.ts`. Foi preciso declarar `@babel/core` e `@babel/runtime` nas devDependencies, porque o `legacy-peer-deps` não instala peers.
